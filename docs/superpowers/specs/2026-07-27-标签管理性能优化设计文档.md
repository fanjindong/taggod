# 标签管理性能优化设计文档

## 背景

`标签之神` 已经支持跨窗口搜索、最近关闭搜索、一键整理、安全去重和工作集管理。当前功能闭环完整，本次不再增加新能力，只处理已经能够用调用次数或复杂度具体说明的热点。

审查发现四个明确问题：

1. 搜索过滤和排序会在比较器中反复计算同一标签的匹配分数。
2. 搜索结果使用方向键移动选中项时，会重新排序并重建整个结果列表。
3. 关闭重复标签时，每个候选标签都会重新查询整个窗口并重建所有重复组。
4. 当标签已经在正确的 Chrome 原生分组中时，整理流程仍会再次创建分组。

搜索热点已用现有函数做过合成压测：1000 个标签、双关键词查询、8 次运行取中位数时，当前纯 JavaScript 路径约为 `154.18ms`；将每个候选的分数只计算一次后约为 `20.18ms`，结果顺序一致。该数据不包含 DOM 重建成本，只用于证明重复计算是真实热点，不作为跨机器的固定性能门槛。

## 目标

- 搜索每次计算中，每个候选标签的匹配分数和最终排名分数只计算一次。
- 方向键只更新新旧选中项的样式、滚动与焦点，不重新过滤、排序或重建列表。
- 重复关闭仍保留“只关闭确认快照与当前安全状态的交集”语义，同时将全窗口查询从按候选次数执行收敛为每次操作一次。
- 重复执行整理时，已处于唯一正确原生分组的标签不再创建新分组。
- 删除已确认无生产调用的旧入口、默认配置和样式，不做无关重构。
- 保持现有中文交互、键盘操作、去重安全边界和分组规则不变。

## 非目标

- 不引入搜索库、虚拟列表、UI 框架或新构建步骤。
- 不改变搜索字段、匹配分值、排序优先级、最大结果数和最近关闭数量上限。
- 不把搜索缓存持久化，不建立需要手工失效的全局缓存。
- 不批量调用 `chrome.tabs.remove()`，原因是每个目标仍需要独立复核和统计。
- 不放宽固定、活动、播放声音或正在跳转标签的保护规则。
- 不实现完整的分组差异引擎，只增加可以确定无变化的快路。
- 不引入完整 Public Suffix List 依赖，不在本次修改主域名识别语义。

## 搜索计算设计

### 单次计分

`getVisibleTabsFromState()` 继续作为纯函数入口。存在搜索词时，先对搜索池做一次映射，为每个候选生成当次计算记录：

```js
{
  tab,
  matchScore,
  rankingScore
}
```

- `matchScore` 由现有 `getSearchMatchScore()` 生成。
- `rankingScore` 等于 `matchScore + getRecentMatchScore()`。
- 当次搜索只读取一次 `Date.now()`，避免同一次排序中的时间边界变化使比较器不稳定。
- 过滤阶段复用 `matchScore`，并保留现有全量文本包含判断作为兼容兜底。
- 排序比较器只读取记录中的 `rankingScore`，不再调用搜索计分函数。
- 排序完成后映射回原标签快照，继续使用现有结果结构。

计算记录只存在于一次 `getVisibleTabsFromState()` 调用内，不增加全局缓存、版本号或失效协议。

### 键盘选中快路

`renderTabs()` 在搜索词、已打开标签或最近关闭状态变化时，仍负责完整计算和渲染。渲染时将当前可见结果保存到弹窗生命周期内的 `state.visibleTabs`，供键盘操作直接读取。

`ArrowUp` 和 `ArrowDown` 只执行：

1. 根据 `state.visibleTabs.length` 计算新索引，保留现有循环选择语义。
2. 从原选中 DOM 项移除 `is-selected`。
3. 给新选中 DOM 项增加 `is-selected`。
4. 将新选中项滚入可见区域。
5. 仅当键盘事件来自结果列表时，将焦点移到新选中项的打开按钮。

`Enter` 直接从 `state.visibleTabs` 取当前项。搜索输入、关闭结果、最近关闭缓存失效和完整状态刷新仍调用 `renderTabs()`，保证数据变化后不使用旧列表。

最近关闭缓存失效时必须同步刷新派生列表：

1. `resetRecentlyClosedTabsCache()` 先清空 `state.recentlyClosedTabs` 并提升版本号。
2. 如当前存在搜索词且没有请求在途，启动 `loadRecentlyClosedTabs()`。
3. `invalidateRecentlyClosedTabs()` 在返回前必须立即调用 `renderTabs()`，使 `state.visibleTabs` 和 DOM 同时移除已失效结果。
4. 异步请求结束时，无论版本是否仍有效，都先将 `state.recentlyClosedTabsLoading` 恢复为 `false`。
5. 请求版本仍有效时，调用 `renderTabs()` 渲染成功结果或失败后的空结果；版本已失效时，丢弃旧响应且不渲染，如当前仍有搜索词，则只启动一次新请求。

无论是否正在加载、新请求是否成功，失效函数都不得在同步刷新前提前返回。否则 `Enter` 会继续读取过期的 `state.visibleTabs`。最终渲染必须发生在 `loading` 已清除之后，避免空结果永久停留在“正在补充”状态。

第一阶段不改成事件委托，不引入虚拟 DOM。去掉方向键的全量重建后，已经解决最明确的列表热点。

## 重复关闭设计

### 一次快照

`closeSelectedDuplicateTabs()` 在校验窗口编号和用户选择后，先沿用现有 `normalizeSelectedDuplicateTargets()` 语义生成确认目标列表：

- 只保留有效整数标签编号和非空 `duplicateKey`。
- 同一 `tabId` 只统计一次；如输入重复提交，保留第一次出现的 `duplicateKey`。
- 该去重后列表是 `closedCount + skippedCount + failedCount` 的统计基数。

随后只调用一次 `queryWindowTabs(windowId)`。

该快照只计算一次 `buildDuplicateGroups()`，并按 `duplicateKey` 建立映射。每个当前重复组只保留同时满足以下条件的候选：

- 编号出现在用户确认快照的 `closeTabIds` 中。
- 编号仍出现在当前重复组的 `closeTabIds` 中。
- 当前重复键与用户确认的 `duplicateKey` 一致。

这个交集保证确认后新出现的重复标签不会被纳入本次关闭。

确认目标如未命中当前重复组、已不在当前 `closeTabIds` 中或重复键已变化，不得从处理列表静默丢弃，而是每个唯一目标计入一次 `skippedCount`。即使整个确认组已消失，返回统计也必须覆盖该组的所有唯一确认目标。

### 删除前复核

每个重复组复用当前快照中的 `keepTabId`。每次删除前，分别用 `chrome.tabs.get()` 读取保留项和目标项的最新状态，并校验：

- 保留项仍存在于原窗口，且规范化网址仍等于 `duplicateKey`。
- 保留项不存在 `pendingUrl`；只要正在跳转，就不能作为本次安全关闭的保留依据。
- 目标项仍存在于原窗口，且规范化网址仍等于 `duplicateKey`。
- 目标项仍不是固定、活动、播放声音或正在跳转的标签。

如保留项不存在、移出原窗口、网址变化或出现 `pendingUrl`，当前重复组的剩余候选全部计入 `skippedCount`，不在关闭过程中重选保留项。这一处刻意保守，可避免引入另一套动态重复组状态机；用户重新扫描即可处理已变化的组。

目标项失效或受保护时计入 `skippedCount`；`chrome.tabs.remove()` 失败时计入 `failedCount`。仍按目标顺序逐个删除，不改变现有统计与错误隔离语义。

## 分组整理设计

### 已正确分组快路

`reconcileWindowGroupsFromTabs()` 在现有最终分组键映射之外，再建立“当前 `groupId` 到最终分组键集合”映射。

当某个应创建的最终分组同时满足以下条件时，直接复用已有 `groupId`，不调用 `chrome.tabs.group()`：

- 该组所有标签的 `groupId` 相同且不小于 `0`。
- 该 `groupId` 只对应当前一个最终分组键，没有混入另一个应被拆分的逻辑组。

快路仍调用现有 `chrome.tabGroups.update()` 写入标题和颜色。为了判断标题和颜色是否变化而额外读取每个原生分组，收益不明确，不进入本次范围。

原有 `groupedCount` 继续表示“本次真正新建的分组数”，与弹窗的“创建 N 个分组”文案保持一致。实现时拆开两个计数：

- `groupIndex` 用于选择颜色；每个成功复用或新建的最终分组都递增一次。
- `createdGroupCount` 只在 `chrome.tabs.group()` 成功返回新组编号时递增，最终以现有 `groupedCount` 字段名返回。

因此，全部复用现有正确分组时 `groupedCount` 为 `0`；复用组和新建组混合时，两者仍按最终分组顺序获得不同颜色，但返回值只统计新建组。

如现有分组同时包含多个最终分组键，或目标组的标签分布在多个原生分组中，继续走现有 `chrome.tabs.group()` 路径。本次不尝试选择“最佳可复用组”。

### 排序局部预计算

`buildOrganizedTabsFromNormalizedSettings()` 已经建立优先分组顺序映射和分组信息映射。排序比较器直接：

- 使用 `isGroupable && priorityGroupOrderMap.has(groupKey)` 判断优先分组，不再对 `priorityGroups` 逐次执行 `some()`。`isGroupable` 门槛必须保留，未达到建组阈值的优先单标签不得因本次优化改变排序。
- 使用本次排序内的惰性主机名映射：只在比较器真正进入同组主机名比较时，才为当前标签执行一次 `getHostnameKey(tab.url || '')`，后续比较从 `Map` 复用。不同主域名的标签不做额外 URL 解析，也不顺带改变待加载网址的排序语义。

映射只在一次整理计算中存在，不为分组规则建立持久编译缓存。

## 删除与收敛

实现时可同步删除以下已确认的闲置内容：

- 没有生产调用的 `queryAllWindowTabs()` 及校验脚本中已无效的赋值。
- 只被校验脚本调用、且语义已由 `reconcileWindowGroupsFromTabs()` 覆盖的 `regroupRestoredTabs()` 及重复用例。
- 从未被运行时读取的 `organizeWithGroups` 和 `duplicateKeepStrategy` 默认配置。
- 在 `popup.html` 和 `popup.js` 中都无引用的 `.stats-grid`、`.stat-item`、`.icon-help-button` 和 `.management-section-label` 样式。

删除前再用 `rg` 确认生产调用；如实现期间已出现新引用，则保留该项。不扩大到全项目 CSS 重写、测试脚本拆分或文档清理。

## 错误处理与兼容

- 搜索计分记录只改变计算方式，不改变对外返回的标签快照。
- DOM 选中项缺失时，键盘快路回退到 `renderTabs()`，避免状态与页面结构失配后无法操作。
- 最近关闭缓存失效时，先同步移除过期的 `state.visibleTabs` 内容，异步加载失败也不得恢复旧快照。
- 最近关闭请求在途中再次失效时，旧请求必须清除 `loading` 且只触发一次后续请求，不得渲染旧响应。
- 重复关闭的全窗口快照读取失败时，整次操作失败且不关闭任何标签。
- 单个重复候选或保留项复核失败时，按安全边界计入跳过，不中断其他重复组。
- 原生分组快路只在归属唯一时命中；无法确认时继续使用现有重建路径。

## 校验策略

本次继续扩展 `scripts/校验插件.js`，不引入测试框架。用调用次数和结果契约验证优化，不用易受机器影响的绝对耗时作为自动校验条件。

需要覆盖：

- 单关键词、多关键词、缩写、子序列、最近分数和最近关闭结果的顺序与优化前一致。
- 一次搜索计算中，`getSearchMatchScore()` 对每个候选最多调用一次。
- 连续按下 `ArrowUp` 或 `ArrowDown` 不调用 `getVisibleTabsFromState()` 和 `renderTabs()`。
- 键盘选择仍循环，`Enter` 仍打开焦点或选中项，关闭按钮仍保留原生回车语义。
- 最近关闭缓存失效且新请求尚未返回时，`state.visibleTabs` 和 DOM 中已不存在旧的最近关闭结果。
- 最近关闭请求返回空结果或失败后，最终渲染时 `state.recentlyClosedTabsLoading` 已为 `false`。
- 最近关闭请求在途中再次失效时，旧响应不被渲染，`loading` 先清除，随后恰好发起一次新请求并渲染最新结果。
- 关闭任意数量的重复候选时，`chrome.tabs.query()` 只调用一次。
- 确认后新增的重复标签不会被关闭。
- 整个确认重复组消失时，其所有唯一确认目标都计入 `skippedCount`。
- 同一 `tabId` 在输入中重复出现时只处理和统计一次。
- 目标跳转、目标受保护、保留项失效或保留项出现 `pendingUrl` 时安全跳过，关闭成功、跳过和失败数量准确。
- 标签已完整位于唯一正确分组时，`chrome.tabs.group()` 不被调用。
- 一次整理同时包含复用组和新建组时，颜色索引按所有最终分组递增，`groupedCount` 只统计新建组。
- 全部复用现有分组时，`groupedCount` 为 `0`。
- 一个原生分组包含多个最终分组键时，仍走现有重建路径。
- 未达到建组阈值的优先单标签排序与优化前一致。
- 不同主域名的标签不调用 `getHostnameKey()`；需要比较主机名时，同一标签在一次排序中最多解析一次。
- 被删除的闲置函数、配置字段和样式无生产引用。


人工验收：

- 在数百个搜索候选中连续使用方向键，高亮、滚动和焦点保持连续。
- 搜索输入、关闭单个结果、恢复最近关闭页面后，可见结果没有使用过期快照。
- 连续关闭多组重复标签，界面统计与实际关闭结果一致。
- 对已经整理正确的窗口再次整理，原生分组不闪烁、不重置折叠状态。

## 分阶段实现

### 第一阶段：搜索与键盘快路

- 搜索候选单次计分。
- 渲染时保存可见结果快照。
- 方向键只更新选中项。
- 最近关闭缓存失效时同步刷新可见结果。
- 补充搜索顺序和键盘调用次数校验。

### 第二阶段：重复关闭

- 重复关闭使用一次全窗口快照。
- 以去重后的全部确认目标作为统计基数。
- 删除前复核保留项和目标项。
- 补充安全边界校验。

### 第三阶段：整理快路与删除

- 复用已正确的原生分组。
- 分离最终分组颜色索引与新建分组计数。
- 预计算优先状态，并在本次排序内按需记忆主机名。
- 删除已确认的闲置代码与样式。
- 补充分组幂等性校验。

三个阶段都可独立校验和交付。后一阶段不应阻塞前一阶段合并。

## 验收标准

- 搜索结果顺序和优化前一致，且计分不再随排序比较次数增长。
- 方向键操作不触发全量搜索或列表重建。
- 最近关闭缓存失效后，过期结果在新请求返回前已不可被键盘选中或打开。
- 最近关闭请求在途中失效时，旧响应不渲染，并且只发起一次后续请求。
- 重复关闭的全窗口查询次数固定为一，且所有现有保护规则继续生效。
- 重复关闭返回的三项统计之和等于去重后的确认目标数。
- 保留项存在 `pendingUrl` 时，当前重复组不关闭任何剩余候选。
- 已处于正确原生分组的标签再次整理时不创建新分组。
- 复用组和新建组混合时颜色顺序稳定，返回的 `groupedCount` 只表示新建数。
- 现有校验脚本、JavaScript 语法检查和人工核心流程验收全部通过。
- 本次不增加任何运行时依赖或构建步骤。

## 自检

- 本设计没有 `TODO`、`TBD` 或未定占位内容。
- 本设计使用当次局部计分记录，没有引入需要失效协议的全局搜索缓存；主机名也只在一次排序内按需记忆。
- 本设计保留原搜索分值、结果上限、键盘循环选择和焦点语义，且最近关闭失效时会同步替换派生列表。
- 本设计保留确认快照、当前快照和删除前复核三道边界，保留项正在跳转时整组跳过，没有用批量关闭换性能。
- 本设计只复用可以证明归属唯一的原生分组，无法确认时仍走现有路径，且分组颜色索引与新建计数分开。
- 本设计将删除范围限定在已确认无引用的内容，不包含全项目格式化或顺手重构。
