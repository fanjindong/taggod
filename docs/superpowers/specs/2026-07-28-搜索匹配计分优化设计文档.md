# 搜索匹配计分优化设计文档

## 结论

本次继续使用现有弹窗内存搜索，不引入搜索库、索引层或持久缓存。文本匹配只读取标签页标题和网址，不再读取主域名、自定义分组名、分组键或短分组名，也删除全部专门缩写识别。优化只处理已经能用当前代码和边界样本证明的相关性问题：新增命中信号不能降低分数，多关键词需要保留命中强弱，搜索相关性不能被任意时间加分反转，当前窗口活动页在同分时不凭刚访问排在其他已打开标签之前，最近关闭结果也不应凭关闭时间获得额外相关性。

实现仍以 `getVisibleTabsFromState()` 为纯函数入口，保留已经完成的“每个候选只计分一次、方向键不重新搜索”性能契约。有搜索词时，当前页与其他候选一样参与计分，但在同分的已打开结果中通过显式当前页标记排在其他页面之后，不伪造时间或修改文本分。点击或回车选中当前页时，前台直接提示“已在当前页”，不发送 `activate-tab`、不写入最近访问也不刷新状态。计分和排序路径不再读取当前时间或计算最近分，结果项仍可使用当前时间格式化访问或关闭时间提示。跨窗口搜索范围、结果数量上限和最近关闭加载方式不变。

## 背景

当前搜索覆盖所有已打开窗口和 Chrome 最近关闭标签页，匹配字段包括标题、网址、主域名、自定义分组名和短分组名。分组状态因此会改变搜索结果和排序，但搜索的职责应止于标签页标题与网址。文本分与最近使用分直接相加：

```text
rankingScore = matchScore + recentScore
```

现有执行热点已经优化，但计分语义仍有以下可复现问题：

1. 匹配采用“第一个命中分支立即返回”，而不是取最高有效信号。现有专门缩写分又与网址、多关键词分支交叉，使最终分数受分支排列影响，而非只由命中质量决定。
2. 多关键词逐词累加后统一封顶 `260`。两个标题词、标题加网址、两个网址词三种强弱不同的匹配都可能变成 `260`，后续排序主要由最近时间决定。
3. 最近一分钟加 `260`。旧的标题完全匹配为 `400`，刚访问的标题包含为 `300 + 260 = 560`，非完全匹配可以压过用户输入的完整标题。
4. 搜索态会重新纳入当前窗口活动页。该页面通常刚被激活，宽泛查询时自然获得最高最近分，但用户并不需要“切换”到正在看的页面。
5. 最近关闭快照把关闭时间写入 `lastAccessedAt`，刚关闭结果因此得到最近一分钟 `260` 分。智能去重刚删掉的重复页会凭“刚关闭”排在保留项前面，回车或点击后又被恢复。
6. ASCII 子序列只要求两个字符，`jt` 一类宽泛输入可以弱命中大量长字符串，再被最近分放大；专门缩写识别又增加了一套边界不明的命中规则。
7. 搜索归一化只做去首尾空白和小写转换，全角字母数字无法命中半角内容；搜索还会读取分组内部键 `custom:`，使分组实现细节泄漏到标签搜索。
8. 多关键词路径会为同一候选重复构造搜索字段；零分候选还会执行一套与正式字段重复的全文包含兜底。

## 目标

- 保证同一候选增加一个更强或额外的匹配信号时，最终文本分不会下降。
- 多关键词继续要求全部命中，并保留标题、网址和弱匹配之间的强弱差异。
- 标题完全匹配以最高文本分自然优先于非完全匹配；同分结果再按来源和时间排序。
- 当前窗口活动页保持可搜索；文本分相同时，其他已打开标签优先于当前页，当前页仍优先于最近关闭结果。
- 选中当前页只在前台显示“已在当前页”，不触发标签激活、最近访问写入或状态重载。
- 最近关闭结果不获得时间加分；关闭时间只用于同类同分结果排序，不做网址重复过滤。
- 删除词首、驼峰和网址等全部专门缩写识别，并将普通 ASCII 子序列收紧为至少三个字符。
- 支持全角与半角兼容搜索，并删除主域名、分组名、分组键和短分组名匹配。
- 每个候选仍只计算一次匹配分和一次字段快照，不新增全局缓存或失效协议。
- 更新排序说明、README 和现有校验脚本，使规则成为可执行契约。

## 非目标

- 不做拼音、同义词、编辑距离、错别字纠正或页面正文搜索。
- 不搜索全量历史、工作集内容或浏览器书签。
- 不为搜索重新设计另一组时间权重；有搜索词时直接删除 `260`、`180`、`100` 三档最近加分。
- 不调整空搜索最近使用列表、搜索结果 `100` 条上限或最近关闭快照上限。
- 不引入 Fuse.js、MiniSearch、虚拟列表、Web Worker、持久索引或服务端能力。
- 不建立跨查询字段缓存；浏览器标签规模尚不需要承担缓存失效复杂度。
- 不按网址、智能去重键或关闭来源隐藏最近关闭结果。用户查询若更明确地命中已关闭页面，应允许该结果按文本质量正常排序和恢复。
- 不通过固定负分或伪造时间下沉当前活动页；只在文本分和来源相同时使用显式当前页标记破平。最近关闭结果不设固定负分，同分时由来源顺序和关闭时间兜底。
- 不增加搜索结果关键词高亮、得分展示、缩写识别或用户可配置权重。
- 不保留按主域名、自定义分组名、分组键或短分组名查找标签页的兼容入口；域名若出现在网址中，仍按网址字段正常匹配。
- 不删除标签分组能力或搜索结果中的分组展示；这些信息只是不再参与匹配和排序计分。

## 搜索归一化

`normalizeSearchText()` 统一执行：

1. 将缺失值转为空字符串。
2. 使用原生 `String.prototype.normalize('NFKC')` 统一全角与兼容字符。
3. 去除首尾空白并转为小写。
4. 将连续空白折叠为一个普通空格。

示意实现：

```js
function normalizeSearchText(value) {
  return String(value || '').normalize('NFKC').trim().toLowerCase().replace(/\s+/g, ' ');
}
```

不移除重音符号，不做语言相关分词。中文继续使用连续子串匹配；英文和数字继续使用空格分词和至少三字符的 ASCII 子序列兜底，不再生成或匹配缩写候选。

## 搜索字段

每个候选只构造一次搜索字段快照：

```js
{
  title,
  url
}
```

- `title`：归一化后的页面标题。
- `url`：归一化后的完整网址。

分组字段不进入搜索快照。标题和网址都不生成任何缩写候选，只参与连续包含和至少三字符的 ASCII 子序列匹配。两个随机非连续字符不再命中；`gpr` 一类三字符输入仍可能作为普通标题子序列弱命中，但不再具有专门的缩写语义或加分。

## 文本计分

### 完整查询分

完整归一化查询在保留字段中的直接命中分保持不变：

| 命中方式 | 分数 |
| --- | ---: |
| 标题完全相等 | `400` |
| 标题连续包含 | `300` |
| 网址连续包含 | `100` |

完整查询分不再采用命中即返回，而是计算所有适用信号并取最大值。

### 单词分

每个关键词分别计算所有适用信号，并取最大值：

| 单词命中方式 | 分数 |
| --- | ---: |
| 标题连续包含 | `180` |
| 网址连续包含 | `80` |
| 标题 ASCII 子序列 | `60` |
| 网址 ASCII 子序列 | `40` |

这里的关键契约是“取最高分”，不是依赖 `if` 分支排列。同一关键词在标题和网址上同时命中时，应取质量更高的信号；完整查询分与关键词分也必须在最后统一取最大值。

单关键词时，`tokenizedScore` 直接等于该词的 `tokenScore`，不加 `100` 基准分。因此标题子序列和网址子序列的单词分仍分别为 `60` 和 `40`。

### 多关键词分

多关键词继续要求每个词都至少得到一个正分。任一关键词为 `0` 时，多关键词分为 `0`。

全部命中时改为：

```text
multiTokenScore = 100 + round(sum(tokenScores) / tokenCount)
```

单词最高分为 `180`，因此多关键词自然落在 `140` 至 `280`，不再需要额外封顶：

| 示例 | 计算 | 多词分 |
| --- | --- | ---: |
| 两个非连续标题词 | `100 + (180 + 180) / 2` | `280` |
| 标题词 + 网址词 | `100 + (180 + 80) / 2` | `230` |
| 标题词 + 标题子序列 | `100 + (180 + 60) / 2` | `220` |
| 两个网址词 | `100 + (80 + 80) / 2` | `180` |
| 两个标题子序列 | `100 + (60 + 60) / 2` | `160` |
| 标题子序列 + 网址子序列 | `100 + (60 + 40) / 2` | `150` |
| 两个网址子序列 | `100 + (40 + 40) / 2` | `140` |

表中是 `multiTokenScore`，不是最终 `matchScore`。若完整查询本身连续出现在标题中，`phraseScore = 300`，最终仍取 `300`；例如标题 `Alpha Beta Guide` 搜索 `alpha beta` 得 `300`，只有两个词分别命中但不连续时才得 `280`。若标题正好是 `Alpha Beta`，则属于标题完全相等，最终得 `400`。该区间仍低于标题连续包含的 `300`，高于单纯网址完整包含的 `100`，同时保留每个词的字段质量。

### 最终文本分

最终文本分取完整查询分与关键词分中的较大值：

```text
matchScore = max(phraseScore, tokenizedScore)
```

单关键词和多关键词都使用上述最终取最大值规则，但只有多关键词使用 `100 + round(average)` 公式。标题连续命中高于网址连续命中和子序列；多关键词时，完整网址包含分 `100` 可能低于逐词计算结果。因此完整查询分与关键词分必须始终取最大值，不能因某个直接命中提前返回。

## 时间只作同分排序

有搜索词时删除 `getRecentMatchScore()` 及 `rankingScore = matchScore + recentScore`。文本匹配分是唯一相关性分数，时间不再改变不同文本质量之间的顺序。

当前页判定收敛为一个前台局部函数：

```js
function isCurrentPage(tab) {
  return Boolean(tab && tab.active && tab.isCurrentWindow);
}
```

空搜索过滤、搜索同分排序、结果“当前页”标注、选中当前页的本地短路和关闭保护都复用 `isCurrentPage()`，不各自重写判定式。当前页与其他已打开标签一样构造搜索字段、计算文本分和准备 `lastAccessedAt`；比较器在文本分和来源相同后，先将其他已打开标签排在当前页之前，再比较时间。其他窗口的活动页因 `isCurrentWindow` 为假，仍按普通已打开标签排序和交互。

每个已匹配候选只准备一个同分排序时间：

```text
最近关闭结果 => sortTime = closedAt
已打开标签 => sortTime = lastAccessedAt
```

时间缺失或非法时按 `0` 处理。最近关闭结果的排序和界面时间提示都必须显式读取 `closedAt`，不得继续借用 `lastAccessedAt`；当前快照即使暂时保留两个同值字段，也不能作为搜索契约。空搜索仍沿用现有最近使用列表，直接排除当前窗口活动页并按 `lastAccessedAt` 排序。

## 搜索排序

每个候选生成一次当轮排序记录：

```js
{
  tab,
  matchScore,
  sortTime
}
```

排序优先级调整为：

1. `matchScore` 从高到低。标题完全匹配为 `400`，自然先于最高 `300` 的非完全匹配，不需要单独的 `exactTitle` 标记。
2. 文本分相同时，已打开标签优先于最近关闭标签。
3. 同为已打开且文本分相同时，非当前页优先于当前页。
4. 同来源同分时，`sortTime` 从新到旧。
5. 时间相同时，当前窗口优先。
6. 标签索引从小到大。
7. 标签编号或结果编号按现有本地化字符串比较兜底。

因此旧的标题包含 `300` 始终先于刚访问的网址包含 `100`，弱子序列也不能凭时间压过更明确的连续命中。多个同分已打开结果中，先将当前页排在其他页面之后，其余结果再按最近访问排序；多个同分最近关闭结果仍按关闭时间排序。

当最近关闭结果与已打开结果文本分相同时，“已打开标签优先”保证切换现有页面；这条规则也适用于当前页，因此智能去重后与当前页同分的关闭副本不会排在它之前。当最近关闭结果拥有更强文本命中时，它仍可排在较弱的已打开结果之前，尊重用户本次查询意图。两类结果即使网址相同也不互相隐藏。

## 计算收敛

现有单次计分记录继续保留，并做以下局部收敛：

- `getSearchMatchScore()` 为候选构造一次 `parts`，多关键词函数直接接收该对象，不再按关键词路径重复调用 `getSearchFieldParts()`。
- 搜索快照只保留标题和网址；确认无其他调用后删除 `getSearchWords()`、`buildAcronymText()` 及缩写匹配分支。
- 删除 `getTabSearchText()` 及过滤阶段的全文包含兜底。标题和网址均已由完整查询和关键词规则覆盖；连续包含结果必然得到正分，该兜底没有独立可达语义。

不预归一化整个 `state.tabs`，不建立跨输入缓存。每次输入在内存中重新生成当轮字段快照，继续沿用现有状态变更边界，避免新增缓存版本管理。

## 用户提示与文档

弹窗“排序说明”调整为：

> 搜索只匹配标签页标题和网址，并先按文本匹配质量排序：标题完全匹配最高，标题连续命中优先，网址连续命中次之，至少三个非连续 ASCII 字符只作低分兜底；多关键词需要全部命中，并按每个词的命中质量计分。文本分相同时已打开标签优先，当前页在同分的已打开结果中排在其他页面之后，再按最近使用或关闭时间排序。

搜索无结果时的辅助提示改为“可尝试标题或网址。”，不再提示主域名或分组名。

不在弹窗中列出全部内部数字，避免说明文字随局部权重调整而频繁变长。`README.md` 删除按主域名、自定义分组名和英文缩写搜索的说明，保留多关键词示例，并补充“普通非连续匹配至少三个字符”。弹窗搜索框占位文案改为“输入标题或网址”；README 引用的使用页面标注图同步删除主域名和分组名搜索说明。

## 兼容与行为变化

本次不修改 storage、消息协议、权限、标签快照字段或最近关闭缓存结构，无数据迁移。

以下变化属于预期：

- 删除词首、驼峰和网址等全部专门缩写识别；三字符以上的输入仍可按普通 ASCII 子序列弱命中。
- 多关键词结果不再普遍挤在 `260`，强标题命中会高于网址组合。
- 搜索不再计算 `260`、`180`、`100` 三档最近分，不同文本质量之间不会被访问或关闭时间反转。
- 标题完全匹配以 `400` 自然排在所有非完全匹配之前，不再需要额外排序标记。
- 当前窗口活动页保持可搜索，结果元信息标注为“当前页”；同分时其他已打开标签排在它之前，它仍排在最近关闭结果之前。选中当前页时只显示“已在当前页”，不发送后台消息或刷新弹窗状态。最近关闭结果保留关闭时间提示和同类同分排序。
- 已打开与最近关闭结果不做网址重复过滤；文本分相同时已打开标签优先，最近关闭结果文本命中更强时仍可排在前面。
- 两字符普通子序列结果会消失，不再为词首或驼峰缩写保留例外。
- 标题和网址都只保留连续包含和至少三字符的 ASCII 子序列匹配。
- 全角英文和数字可命中半角内容。
- 主域名、自定义分组名、分组键和短分组名不再参与搜索；域名仍可通过完整网址匹配，但只按网址质量计分。

以下行为保持不变：

- 空搜索仍只展示已打开标签的最近使用列表，并排除当前窗口活动页。
- 多关键词仍采用 AND 语义。
- 最近关闭结果仍只在有搜索词时异步加载。
- 关闭窗口结果仍按 Chrome 原生窗口会话粒度恢复。
- 空搜索最近使用顺序、搜索结果数量和最近关闭数量上限不变。
- 除选中当前页改为前台本地提示外，点击、回车、方向键、关闭普通结果和恢复最近关闭结果的交互不变。

## 校验策略

继续使用现有 `scripts/校验插件.js`，不引入测试框架。新增表驱动断言覆盖：

### 归一化与字段

- `ＡＢＣ` 可以标题完全匹配 `ABC`，得分 `400`。
- 连续空白折叠后，多关键词语义不变。
- 标题和网址相同的两个标签，无论主域名、分组名、分组键和短分组名如何变化，匹配分都必须相同。
- 自定义分组 `custom:项目 A` 的标签在标题和网址均不含 `项目 A` 时，查询 `项目 A` 或 `custom` 均不得命中。
- 已归入自定义分组的 `https://github.com/...` 标签搜索 `github.com` 得到网址连续包含分 `100`，不得因主域名或分组字段升为更高分。

### 单词与弱匹配

- 标题完全匹配、标题包含、网址包含分别得到 `400`、`300`、`100`。
- `GitHub Pull Requests` 搜索 `gpr` 只得到普通标题子序列分 `60`，不存在独立缩写分。
- 同一标签网址增加 `/gpr` 后得到网址完整包含分 `100`，证明增加更强命中信号不会降分。
- `GitHub Pull Requests` 搜索 `gh` 或 `pr` 时，在标题和网址都不连续包含查询的前提下不得命中。
- 标题不命中时，`https://google.com` 搜索 `hg` 不得凭网址结构命中。
- 三字符标题子序列得到 `60`，网址子序列得到 `40`。
- 两字符普通子序列不得命中，没有词首或驼峰例外。
- 生产代码不再包含 `getSearchWords()`、`buildAcronymText()` 或其他缩写候选的构造与匹配分支。

### 多关键词

- 两个不连续的标题词得到 `280`；标题 `Alpha Beta Guide` 搜索 `alpha beta` 得 `300`，标题正好是 `Alpha Beta` 时得 `400`。
- 标题词加网址词得到 `230`。
- 标题词加标题子序列得到 `220`。
- 两个网址词得到 `180`。
- 两个标题子序列得到 `160`。
- 标题子序列加网址子序列得到 `150`。
- 两个网址子序列得到 `140`。
- 三个关键词分别得 `180`、`80`、`60` 时，按 `100 + round(320 / 3)` 得到 `207`。
- 任一关键词未命中时得分 `0`，候选不进入结果。

### 排序

- 旧的标题完全匹配 `400` 排在刚访问的标题包含 `300` 之前。
- 旧的标题完全匹配排在刚访问的网址或弱匹配之前。
- 旧的标题包含 `300` 排在刚访问的网址包含 `100` 之前。
- 当前页标题完全匹配 `400` 时，排在其他已打开标签的标题包含 `300` 之前；只有文本分相同时才下沉当前页。
- 当前页与其他已打开结果文本分相同时，其他页面排在当前页之前，且不依赖两者的 `lastAccessedAt`。
- 当前页与最近关闭结果文本分相同时，当前页作为已打开结果排在前面。
- 最近关闭结果文本分更高时，仍排在文本命中较弱的当前页之前。
- 其他窗口的活动页不视为当前页，使用自身 `lastAccessedAt` 参与同分排序。
- 已打开与最近关闭结果文本分相同时，已打开标签排在前面。
- 最近关闭结果标题完全匹配时，仍排在仅有较弱文本命中的已打开结果前面。
- 多个同分最近关闭结果之间按关闭时间从新到旧排序。
- 最近关闭测试必须令 `closedAt` 与 `lastAccessedAt` 故意不同，证明排序和界面提示都读取 `closedAt`。
- 多个同分且均非当前页的已打开结果之间按最近访问时间排序。
- 分数、来源、当前页标记和时间都相同时，依次按当前窗口、标签索引和结果编号稳定排序。
- `sortTime` 缺失、为负数、`NaN` 或 `Infinity` 时均按 `0` 处理，不得让比较器返回 `NaN`。
- 已打开与最近关闭结果网址相同且都命中查询时，两者都保留，不增加网址去重过滤。

### 当前页交互

- 鼠标点击当前页结果时，只将状态提示设为“已在当前页”。
- 键盘选中当前页后按 `Enter` 与鼠标点击走同一本地短路。
- 两条路径都不调用 `runAction('activate-tab')`、不发送后台消息、不调用 `loadState()`，因此不会重写最近访问时间。
- `active: true` 但 `isCurrentWindow: false` 的其他窗口活动页不得显示“当前页”，点击或回车必须调用 `runAction('activate-tab')`。
- 其他已打开标签仍执行现有 `activate-tab` 路径，最近关闭结果仍执行恢复路径。

### 性能契约

- 一次 `getVisibleTabsFromState()` 中，每个候选仍只调用一次 `getSearchMatchScore()`。
- 当前页不走特殊计分快路，与其他候选一样只调用一次 `getSearchMatchScore()` 和一次 `getSearchFieldParts()`。
- 多关键词候选只构造一次搜索字段快照。
- 有搜索词时，计分与排序路径中的 `getVisibleTabsFromState()` 和排序比较器均不调用 `Date.now()`；结果时间提示的格式化不在此契约内。
- 方向键继续不调用 `getVisibleTabsFromState()` 和 `renderTabs()`。
- 删除 `getTabSearchText()` 后，标题和网址连续包含用例仍全部可见，分组字段不再产生结果。
- 排序说明、无结果提示和搜索框占位文案只描述标题与网址，不再出现主域名、分组名或缩写搜索入口；当前页结果元信息明确标注“当前页”，其他窗口活动页仍标注为“其他窗口”。
- `assets/插件使用页面标注.svg` 不再宣称主域名、分组名或缩写可搜索，并人工确认重新生成的 PNG 文案一致。

人工验收：

- 搜索 `gpr` 时，标题为 `GitHub Pull Requests` 的结果只作为三字符子序列弱命中；网址明确包含 `gpr` 时应升为网址连续命中档位。
- 搜索两个关键词时，两个标题词命中的页面高于标题加网址命中的页面。
- 修改标签所属分组后，同一标题和网址的搜索结果与分数不变；仅输入自定义分组名不会找到标签。
- 搜索 `github.com` 仍可通过网址找到对应标签，但不再因主域名或分组状态获得额外分数。
- 在当前 GitHub 页面搜索 `github` 时，当前页仍可见并标注“当前页”；与其他已打开结果同分时排在它们之后，点击或按回车只提示“已在当前页”。
- 在其他窗口的 GitHub 活动页上命中同一查询时，该结果标注“其他窗口”，点击或回车仍正常切换窗口和标签。
- 智能去重保留当前页并刚关闭副本后，两者文本分相同时当前页排在关闭副本之前。
- 刚访问的弱文本命中不再压过更明确但较早访问的结果。
- 搜索明显指向已关闭页面时，该结果仍可按更强文本分排在已打开结果前面并恢复。
- 已打开与最近关闭结果网址相同且均命中时，两者都可见，不做重复过滤。
- 输入全角英文数字可以命中对应半角标题或网址。
- 输入两个随机非连续字母不产生弱匹配，词首或驼峰两字母也没有例外。
- 标题无命中时，两字符输入不会仅凭网址协议名或域名段首字母命中。

## 验收标准

- 匹配分满足单调性：增加更强或额外命中信号不会降低文本分。
- 文本匹配字段只包含标题和网址，主域名与全部分组字段不会改变是否命中或匹配分。
- 多关键词强弱关系符合 `标题 > 网址 > 弱匹配`，不再普遍同为 `260`。
- 标题完全匹配始终先于非完全标题结果。
- 当前页保持可搜索；文本分相同时已打开标签优先于最近关闭结果，同为已打开结果时其他页面优先于当前页，再按有效访问或关闭时间排序。`isCurrentPage()` 统一用于过滤、排序、标注、选中短路和关闭保护；选中当前页只显示本地提示，不触发标签激活、最近访问写入或状态刷新，其他窗口活动页仍正常切换。
- 全角兼容、删除全部缩写识别以及两字符弱匹配行为均符合设计。
- 每候选单次计分、单次字段构造和方向键快路保持有效。
- 不新增依赖、权限、构建步骤、持久缓存或共享模块改动。
- 自动校验、语法检查和 `git diff --check` 全部通过。
